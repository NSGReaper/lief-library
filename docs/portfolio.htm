Reading Hero Lab Saved Portfolios

Portfolios saved by Hero Lab version 4.1 (or later) are saved in the format described in this document. This allows third-party tools to open a Hero Lab saved portfolio, read content out of it, and then do whatever they want with that content - display it on a web site, convert it to some other format, or anything else they might want to do.

This document is intended for authors of third party tools who want to add support for reading Hero Lab saved portfolios. You don't need to know anything about this if you're just a normal user of Hero Lab - in normal use, the product automatically saves and load files just like any other Windows or Mac application. This is only important for people who are making their own applications which will interact with Hero Lab's saved files.

Getting Started

If you're planning to use the contents of this document, it's critical that you read the Important Notes section, below. This section outlines some very important things for you to be aware of when working with the format.

Readers of this document are assumed to have a basic knowledge of software development, including zip files and XML. If you don't have that, we recommend you read up those subjects before continuing.

Please note that when the document below says that you "must" or "must not" do something, that is a strict requirement for interacting with the saved portfolio. Failing to meet these requirements in your tool may result in your tool breaking as a result of future changes to Hero Lab.

Saved Portfolio Format

Portfolios saved by Hero Lab version 4.1 or later are zip files. Your tool can use any standard compression library to decompress them and look inside. When you do, here's what you'll find:

  • One file named index.xml. This is the Public Index of the saved portfolio, in XML format.
  • One or more folders containing statblocks and images. The names of these folders are not fixed, and must be read from the Public Index file.

The only file you can assume to be present is the Public Index file. You must read the locations of all other files and folders from the public index file, instead of assuming they're in a specific location. This will make your app more resilient against potential future changes to the saved portfolio file format.

The Public Index

The public index is always contained in a file named index.xml in the root of the saved portfolio. It's a standard XML file whose format can be found in our DTD list. This is the directory that points you to all the interesting parts of the file.

To explain how the public index file works, here's an example public index for a saved portfolio for the Pathfinder game system. (Refer to the DTD if you want a canonical list of which XML nodes must or may be included in the file.) 

<?xml version="1.0" encoding="ISO-8859-1"?>
<document signature="Portfolio Index">

The XML declaration and fixed signature are present at the start of every public index file. Note that the encoding here is just an example and may change in the future. Your tool should be prepared for Hero Lab to output files in any reasonable encoding. 

  <game name="Pathfinder Roleplaying Game"
    folder="pathfinder" publisher="Paizo Publishing, LLC" url="http://www.paizo.com/">
    <gameinfo>These data files are published under license from Paizo Publishing, LLC. © Paizo Publishing, LLC. All rights reserved. Paizo Publishing, LLC, and Pathfinder are registered trademarks of Paizo Publishing, LLC; Pathfinder Roleplaying Game, Pathfinder Society, Pathfinder Chronicles, Pathfinder Modules, and Pathfinder Companion are trademarks of Paizo Publishing, LLC. The Pathfinder Roleplaying Game is © 2010-2017 Paizo Publishing, LLC.</gameinfo>
    <version version="7.1" primary="7" secondary="1" tertiary="" build=""></version>
    </game>

The game node describes the game system the portfolio was saved for. If you're doing something that requires special handling of one or more game systems, you must discriminate on the folder rather than the name. The folder is guaranteed to remain unchanged for the life of the game, whereas it's possible the name may change.

If a version is displayed here, it's the product-specific version of the data files for the game system. 

  <program name="Hero Lab" url="http://www.wolflair.com">
    <programinfo>Hero Lab® and the Hero Lab logo are Registered Trademarks of LWD Technology, Inc. Free download at http://www.wolflair.com<![CDATA[
]]>Pathfinder® and associated marks and logos are trademarks of Paizo Publishing, LLC®, and are used under license.</programinfo>
    <version version="4.1" primary="4" secondary="1" tertiary="" build="328"></version>
    </program>

The program node describes the program used to output the file (in this case, Hero Lab). It's possible that other tools may generate this file format in future, in which case they should set up this section appropriately for themselves. 

  <handlers>
    <handler name="Hero Lab" folder="herolab"></handler>
    </handlers>

Any tools which can "handle" opening the portfolio are listed here, with a pointer to their proprietary data folder. In this case, this portfolio has proprietary data for Hero Lab, contained in the "herolab" folder. You must never touch the contents of folders specified here, unless you're the tool itself. 

  <characters>
    <character name="Hakkon Truesilver" summary="Human Bbn 4 Clr 3 – CR 6" allegianceid="algAlly" allegiancename="Ally to Party" playername="" characterindex="1">

Summary details about each character are listed in their character node. These are ideal for extraction and quick display if you want to show information about the portfolio. 

      <statblocks>
        <statblock format="text" folder="statblocks_text" filename="1_Hakkon_Truesilver.txt"/>
        <statblock format="html" folder="statblocks_html" filename="1_Hakkon_Truesilver.htm"/>
        <statblock format="xml" folder="statblocks_xml" filename="1_Hakkon_Truesilver.xml"/>
        </statblocks>

Various different formats of statblocks may be present for each hero. Hero Lab generates text & HTML Statblocks for all heroes, and XML Statblocks for top-level heroes. See the appropriate sections for more information on these statblocks.

Note that each statblock specifies both the folder in which you can find it and the filename of the statblock. You must use these to find the file for the statblock, rather than making guesses based on the name of the hero or other data. 

      <images>
        <image filename="1_2_Hakkon_Truesilver.jpg" folder="images"/>
        </images>

Images can also be present for each hero, if specified by the user. See the Images section for more information. 

      <minions>
        <character name="Falcon" summary="Hawk – CR 1/3" allegianceid="algAlly" allegiancename="Ally to Party" playername="" characterindex="2">
          <statblocks>
            <statblock format="text" folder="statblocks_text" filename="1.1_Falcon.txt"/>
            <statblock format="html" folder="statblocks_html" filename="1.1_Falcon.htm"/>
            </statblocks>
          <images></images>
          </character>
        <character name="Horse, heavy (combat trained)" summary="Horse, Heavy – CR 2" allegianceid="algAlly" allegiancename="Ally to Party" playername="" characterindex="3">
          <statblocks>
            <statblock format="text" folder="statblocks_text" filename="1.2_Horse_heavy_combat_trained.txt"/>
            <statblock format="html" folder="statblocks_html" filename="1.2_Horse_heavy_combat_trained.htm"/>
            </statblocks>
          <images>
            <image filename="1_3_Hakkon_Truesilver.jpg" folder="images"/>
            </images>
          </character>
        </minions>

Many characters can also have minions - sub-characters under the primary character with their own statblocks and images. As you can see, these look a lot like regular characters, although no XML statblocks are present (see the XML Statblocks section for details on why). 

      </character>
    <character name="Mountain Guide" summary="Human Com 2 War 1 – CR 1" allegianceid="algAlly" allegiancename="Ally to Party" playername="" characterindex="4">
      <statblocks>
        <statblock format="text" folder="statblocks_text" filename="2_Mountain_Guide.txt"/>
        <statblock format="html" folder="statblocks_html" filename="2_Mountain_Guide.htm"/>
        <statblock format="xml" folder="statblocks_xml" filename="2_Mountain_Guide.xml"/>
        </statblocks>
      <images></images>
      </character>
    </characters>
  </document>

Any number of top-level heroes may be present in the file, along with their statblocks, images, and minions.

The "characterindex" attribute listed here can be used to identify the character within the XML Statblock for the top-level hero. For example, if the characterindex attribute here is set to "3", look in the XML Statblock for a character element with characterindex="3", and you'll have found the character element for that character. This can help distinguish between different minions in the same file, and link them to the appropriate images listed in this file.

Text & HTML Statblocks

Text & HTML statblocks are located in various folders in the compressed file. These folders do not have fixed names, so you must retrieve the location of any statblock from the Public Index of the saved portfolio before trying to access it.

A statblock is simply a text or HTML summary of the hero, intended to be read by humans. The specific format of the statblock is generally defined by the publisher of the game system, and Hero Lab tries to adhere as closely to that format as possible. Generally, each hero listed in the public index file will have a text statblock and an html statblock defined for it, with a folder and file name specified for each one. This should let you easily find the full path to the statblock you want, so you can read it into your tool and display it to the user (or save it for later display).

No guarantees are made about the format of a text or HTML statblock. The content or format may well change between different versions of Hero Lab or the game system data files. All you should be doing with a text or HTML statblock is reading it in and displaying it to the user (or saving it for later display). You must not read data out of a text or HTML statblock to use elsewhere in your program. For example, if you want to calculate the total XP value of an encounter, you must read the XP values out of the XML statblock, rather than the text or HTML statblock. Failure to do so may result in your tool breaking as a result of future changes to Hero Lab.

It's possible that a hero may have no text or HTML statblock defined for it. If so, there will be no statblock listed for that hero in the public index file. You must not assume that a hero will have any statblocks defined for it, although they generally will.

It's also possible that future versions of Hero Lab or other tools might generate a statblock in a different format (for example, JSON or markdown). If so, those statblocks will be noted in the public index file with the appropriate format.

Each text or HTML statblock is guaranteed to have a unique name, but that name may not be exactly the same as the name of the hero it refers to. You must make no assumptions about the file names, and must only access them via the public index file, which includes specific file names for the statblocks. These file names may change between saves of the portfolio within Hero Lab.

XML Statblocks

XML statblocks are located in various folders in the compressed file. These folders do not have fixed names, so you must retrieve the location of any statblock from the Public Index of the saved portfolio before trying to access it.

An XML statblock is different from a text or HTML statblock because it's intended to be read by software, not by humans. Parsing an XML statblock with an XML parser will return a structured document describing the character in a way that's very easy to navigate with a program. This allows you to write a tool that pulls out information from the statblock, without having to parse the text or HTML from a file whose format may change without warning.

The XML statblock format for a game system is the same as the custom output XML format, which is defined in the manual for that game. All games that support custom output provide a DTD file that describes the structure of that output. These formats may change in the future, but our intent is to make only additive changes (adding new information, rather than removing information). That means that even if we change the XML output format, your code to read the data should still work, as long as you make sure to ignore elements and attributes that you find in the file.

There's another important difference between XML statblocks and text statblocks. XML statblocks are only defined for top-level heroes, not minions, as described in the documentation for the public index, above. That means that if you want to find the XML statblock for a minion, you must open the XML statblock of its ultimate parent, and search for the minion node inside it.

Generally, each top-level hero listed in the public index file will have an XML statblock defined for it, with a folder and file name specified for each one, just like a text statblock.

It's possible that a hero may have no XML statblock defined for it. If so, there will be no statblock listed for that hero in the public index file. This can happen if the game system in Hero Lab doesn't support custom output, or if the portfolio was saved by a tool that doesn't support custom output (for example, Hero Lab Starter Edition).

Each XML statblock is guaranteed to have a unique name, but that name may not be exactly the same as the name of the hero it refers to. You must make no assumptions about the file names, and must only access them via the public index, which includes specific file names for the statblocks.

Images

Images statblocks are located in various folders in the compressed file. These folders do not have fixed names, so you must retrieve the location of any images from the Public Index of the saved portfolio before trying to access it.

Images are provided in whatever format they were in when the user added them to the saved portfolio. This will typically be PNG or JPG format, but could also be other formats supported by Hero Lab (GIF, TGA, BMP, etc).

Each image is guaranteed to have a unique name, but that name may not necessarily reference the name of the hero which uses that image. You must make no assumptions about the file names of images, and must only access them via the public index or XML statblocks, which include specific file names for the images for heroes.

Important Notes

  • The Hero Lab saved portfolio format is the same on both PC and Mac, so it doesn't matter which operating system users save their files on. Your tool should be able to read saved files from either platform without any special handling.
  • In addition to the files and folders described above, there will also be proprietary files and folders present in the saved portfolio. You must not edit or change this data in any way. Doing so will likely result in Hero Lab not being able to open the saved portfolio at all. The format of this proprietary information may change without warning, so you should not assume anything about it, or even try to read information out of it.
  • As noted above, the format of certain files may change, and the names of folders may change. You must not hard-code folder or file names that you should be reading out of the public index file, or future changes to Hero Lab may result in your tool no longer working.
  • You must treat the saved portfolio format as read-only. Any changes you make to the statblocks will be ignored by Hero Lab the next time it reads the saved portfolio in.
  • Further, you must not add any files to the saved portfolio format. Hero Lab will ignore those files, and they will be lost the next time you save the portfolio in Hero Lab. (We may relax these two restrictions in the future, but for now this is how it is.)
  • Hero Lab began using this file format in version 4.1. Saved portfolios from versions of Hero Lab before then were a proprietary XML format, not a zip file. If you try to open a Hero Lab saved portfolio as a zip file and it fails, you probably have a portfolio from a previous version of Hero Lab, and should prompt the user to update it by simply opening it, making any change, then saving it in a new version of Hero Lab.
  • It's our intent that other products can use this format to generate their own saved portfolio files, which should then be able to be imported by any tool that reads the portfolios generated by Hero Lab itself. However, Hero Lab will not be able to load saved portfolios generated by other tools, and other tools must not put anything in the "herolab" proprietary folder when generating the saved portfolio.
